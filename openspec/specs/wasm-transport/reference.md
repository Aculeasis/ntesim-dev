# WebAssembly parity and client contract

Detailed interface and model reference for this [capability](spec.md). Requirements and scenarios live in that spec; this reference retains formats, bounds and technical rationale.

Governs the thin WebAssembly adapter `ntesim-wasm`, typed bindings and versioned binary transport, zero-epsilon parity guarantees with the native engine, and explicit separation of environment-specific wrapper metadata.

## Delivery and verification schedule

Native mechanics changes use Rust/native validation. Source/report APIs and WASM adapters select current native/WASM builds and bounded Worker smoke checks; web/JS changes and --full retain complete parity/browser checks. Each receipt applies only to its actual checked artifacts. See [check selection](../../../docs/DEVELOPMENT.md#choosing-checks).

`invoke("inspect_script", {"source": ...})` returns the same structured party/diagnostics as native `inspect-script`. `compile_script` also returns that party, retaining it on rotation-lowering failure after a valid configuration. [Script API](../script-inspection/reference.md) owns fields, exactness, ranges and limits; neither endpoint executes the rotation to inspect stats.

## 1. Architectural principles

`ntesim-wasm` is a thin, self-contained WebAssembly adapter layer compiled directly over `ntesim-core` and `ntesim-contracts`.
- **Single engine core:** WebAssembly executes the exact same Rust code, arithmetic algorithms, PCG-32 RNG implementations, and discrete-event schedulers as the native CLI.
- **Pinned binding generation:** `wasm-bindgen` and its local CLI are pinned to 0.2.128. Generation is a build step; running the bundled engine requires no toolchain or external service. This implements [ADR 0008](../../../docs/decisions/0008-architecture-consolidation-and-hygiene.md).
- **Dual-target compilation:** Compiles as `cdylib` for the `wasm32-unknown-unknown` target and as `rlib` for native target architectures (`x86_64-pc-windows-msvc`, Linux, macOS), enabling automated native unit testing alongside WebAssembly execution.
- **Embedded reference assets:** Bundles frozen reference data (`coverage.json`, `variants.csv`, `conditions.json`) via `include_str!` so browser and worker environments operate out of the box offline with zero external network fetch requirements.

## 2. Typed bindings and binary transport

`transport(action: string, input: string, json: boolean): Uint8Array` is generated by `wasm-bindgen`. Inputs retain exact JSON tokens through the shared `stringifyWasmInput`; generated glue owns allocation, copying and release, including returned buffers. No authored Rust unsafe exports, host pointer arithmetic or caller alloc/dealloc API remains. Each engine gets an isolated generated closure, so loading a second instance cannot redirect an earlier engine's imports, memory or prepared cache.

Production uses `json=false`. `json=true` is an explicit lossless JSON export/diagnostic baseline for paired measurements. Both modes serialize the same complete report. Binary transport preserves the decoded JSON schema, partial failures, provenance, exact fractions and environment isolation. The returned array is owned by JavaScript: generated glue copies it once before releasing Rust storage. This is binary transport, not a borrowed zero-copy memory view. Worker UI messages still use structured clone.

### 2.1 NTE wire v1

Every frame starts with bytes `4e 54 45 01` (`NTE`, version 1). Multi-byte words are little-endian. Containers terminate with tag 8. The string dictionary is scoped to one frame and assigns indices in definition order.

| Tag | Payload | Decoded representation |
| --- | --- | --- |
| 0 / 1 / 2 | none | null / false / true |
| 3 | IEEE f64, 8 bytes | number; safe integers are exact |
| 4 | u32 byte length, UTF-8 | string, appended to dictionary |
| 5 | u32 dictionary index | previously defined string |
| 6 / 7 | array items / alternating string keys and values, then tag 8 | array / object |
| 9 | a tag 4 or 5 numeric string | exact integer decimal string above JS safe range; otherwise number |
| 10 | a tag 4 or 5 JSON string | existing borrowed raw provenance decoded with the lossless JSON parser |

Serde serializers see the same human-readable representation as JSON. Typed i128/u128 and `serde_json` arbitrary-precision numbers retain exact spelling. Nonfinite floats follow JSON's null policy. String pooling compresses repeated field names, identifiers and raw static provenance across a batch without deduplicating mutable decoded report objects. Timeline events and trial observations are binary records; pre-existing `RawValue` metadata remains JSON inside the pooled frame. Decoders reject truncated frames, unknown versions/tags, invalid references/UTF-8/numbers, trailing bytes and excessive nesting. `__proto__` is an ordinary own property, as in JSON.parse.

### 2.2 Actions and clients

Admitted Arc player-input receipts include an optional resolved `ability_id`.
Delayed weapon hits can use this actual input parent alongside the ordinary
ability ledger. Clients check command, owner, ability and nonfuture admission
before aggregation/replay; they do not reconstruct Arc eligibility or damage.
Non-Arc receipts omit the field and historical receipts remain decodable. See
[ADR-0012](../../../docs/decisions/0012-admitted-arc-input-identity.md).

Reaction ownership replacement preserves the originating switch separately from its new damage owner. The `esper_cycle_replacement` report origin also references the exact earlier hit in the same receipt vector; clients validate the owner, causal ordering, time and target before constructing replay events. Historical Support/ordinary Cycle origins keep their representation. This is a structural transport boundary, not browser-side reaction logic; see [ADR-0011](../../../docs/decisions/0016-spread-replacement-causality.md).

For an implicit DSL owner change, compilation emits a distinct switch command
before the requested ordinary action or player input. Support belongs to that
admitted switch; recovery can reject the following command while preserving
the Support occurrence and any already delivered hits in the partial report.
The rejected command has no admission occurrence. Actual Worker/native/WASM
checks cover both bound owners with attacks and dash inputs, valid partial
replay, rejected origin/participant/role tampering and exclusion from successful
trial aggregation. These checks preserve the distinct command identities.

The action router supports `version`, `simulate_rotation`, `simulate_game`, `simulate_game_batch`, `simulate_game_program`, `simulate_game_program_batch`, `run_batch`, `verify_tabular`, `enumerate_compositions`, and `invoke`. Batches reject seed ranges that overflow u64. Each seeded execution still starts fresh combat state; preparation caches do not cache simulation state.

`crates/wasm/js/runtime.js` is the shared Node/browser runtime, with `ntesim.js` as its CommonJS entry; Studio's typed adapter only adds presentation contracts and diagnostics. Legacy internal call labels are normalized by this runtime; no C-ABI symbols are exported. Generated JS, declarations and the processed binary live in `target/wasm-bindgen/`. `tools/cargo.py build ... --target wasm32-unknown-unknown` performs version-checked generation after a successful compilation. Current consumers load `target/wasm-bindgen/ntesim_wasm_bg.wasm`; raw Cargo output is not runnable without processing. HTTP/MIME/streaming behavior and isolated Worker operation remain checked.

## 3. Metadata isolation

### Live source trial sessions

`invoke("start_source_trials", compiledSourceProgram)` validates the current
`compile_source` artifact and replaces the instance's prepared trial session.
Failed initialization clears the previous session. Trial counts and the complete
seed interval must be JavaScript safe integers; there is no application trial
cap. `step_source_trials` accepts `{offset,count,elapsed_ms}` with a contiguous
completed offset and a transport chunk of 1..25 trials. Each seed executes the
authored live program in fresh combat state; chunking never precompiles branches.

The response contains the first complete source execution, sample deltas,
Rust-owned aggregate observations and an optional failed source execution.
Failure seals the session and never enters statistics. The completed prefix
remains observable. Worker cancellation destroys the instance; the session is
not a serialized combat checkpoint. `aggregate_trials` exposes the same Rust
collector for structured reports with a declared request/count and elapsed time.
`run_source_sample` accepts `{compiled,seed}` and returns the complete live source
execution with its own actual request/occurrences. It does not modify the active
trial session or reuse the first seed's generated commands.
`snapshot_source_trials(elapsed_ms)` reads the admitted prefix without running
another seed. The Worker supplies its measured wall time after a completed chunk
so throughput includes that chunk's execution; Rust computes the summary.

`resume_source_trials` accepts `{compiled,samples,elapsed_ms}` for a nonempty,
incomplete delivered prefix. It clears any previous session, validates the
compiled identity, reruns the retained seeds, compares every sample field—including
paired relative and absolute rates and shield capacity—and rebuilds the collector
from native reports. The ordinary update shape returns the reproduced prefix and
first execution. Altered values or superseded single-scalar shapes are rejected
without leaving an active session. Resume does not accept caller-authored aggregates
or serialize in-flight combat state; see [browser lifecycle](../../../docs/BROWSER_LIFECYCLE.md).

`search_source_reports` accepts `{request,checkpoint_json?,max_new_trials}` and
uses the same bounded authored source search as the CLI. It returns `search`,
exact `report_json` and exact `checkpoint_json`. Pass checkpoint text unchanged
to a new Worker; decoded wide integer observations must not be reserialized as
checkpoint inputs. Rust retains source/engine identity, receipt verification,
event/byte budgets and complete eligible candidate rankings. Seeds must be safe
JavaScript integers; native search retains its 1..64000 new-trial boundary, and
report/checkpoint text has a 64 MiB browser transport limit. The existing `INVOKE`
Worker command transports this action without a second search implementation.

`export_source_report` accepts `{compiled,seed}`, checks the current source
artifact and reruns the selected seed through source and native replay. It
returns the native `SourceReportExport` as `report`, exact Rust-authored JSON as
`report_json`, and the CLI's named `csv_tables`. JSON text preserves integer
tokens beyond JavaScript's safe range. Decoded presentation receipts are never
re-serialized as native inputs: dynamic JSON observations can contain unsafe
integers represented as strings. The UI verifies the returned execution against
the selected sample. `replay_source_report({report_json})`
verifies a portable export (up to 64 MiB), retaining failed/incomplete status.
Its shared Rust verification response is identical to native `replay-script`,
including source/input/request identities, success/completion, quality,
strict readiness and exact damage analysis.
`compare_source_reports({baseline,candidate,request})` uses the native bounded
source comparison and returns `comparison` plus exact `report_json`. Shared
seeds, context checks, combined budgets and failed-run exclusion are unchanged;
these operations do not modify the active trial session.

`research::trials::studio` validates native state/damage/energy receipts before
committing an observation. It owns actor/source/target/action/field-time and
timeline aggregation, population deviation and interpolated empirical quantiles.
Per-trial rates (DPS, retained/granted EPS, HPS) and available shield capacity (SHP)
are transported as paired `{ relative, absolute }` fields (`TimeBasisPair<T>`),
alongside paired aggregates and actor/source/target contribution DPS. Per-trial
rates use actual elapsed combat time for the respective basis, including early
victory; zero relative duration leaves relative rates as `null` while absolute
rates evaluate against the positive wall time. Available shield capacity reflects
native time-weighted averages under the dual-clock model ($C(a)\,da$ vs $C(a)\,dR(a)$).
Canonical damage analysis, candidate comparison eligibility, and Team list
rankings remain strictly relative DPS. Timeline bins cover the declared horizon
with positive widths and at most 240 bins. Numerical chart summaries are
floating-point presentation values; raw reports retain exact fractions. Quality
flags come from admitted reports; sampling never upgrades model evidence. Seed
variation describes the declared model and does not measure model uncertainty.

Card H1 mandates that environment-specific wrapper metadata must remain explicitly separated from core gameplay output:
- Direct endpoints (`ntesim_wasm_simulate_game`, `ntesim_wasm_simulate_rotation`, etc.) return unaugmented, pure core simulation reports matching the decoded native CLI report exactly.
- The universal envelope endpoint (`ntesim_wasm_invoke`) wraps the result:
```json
{
  "status": "ok",
  "action": "simulate_game",
  "environment": {
    "adapter": "ntesim-wasm",
    "target_arch": "wasm32",
    "runtime_model": "browser-worker-or-node",
    "content_cutoff": "2026-10-04",
    "parity_verified": false
  },
  "data": { ... }
}
```
All environment-specific context is placed inside `environment`. The `data` property contains the exact unaugmented core response.

`parity_verified` remains false in runtime metadata: the adapter cannot certify its own build. Parity is established separately by an external verification receipt bound to the exact native and WASM artifacts.

## 4. Zero-epsilon parity verification

Current primary Damage is a checked integer sum of rounded hit receipts,
transported exactly as `N/1` for report totals and decimal wide integers in
compact bins. Statistical presentation converts each complete integer sum once;
DPS remains fractional. Parallel observations carry actual report quality, and
aggregation rejects disagreement with the first trial.
Failed or incomplete source execution cannot produce successful observations.
Successful batch trials emit compact observations. Explicit samples and failed
seeds use the detailed report path. Parallel commits advance in seed order,
including selection of the earliest failed seed, and cap outstanding chunks
at twice the number of compute Workers. Stop releases pending requests.
The older fractional-total figures below are historical verification results
under the former statistics policy, not current rounded-total expectations.

## 5. Universal TypeScript/JavaScript client

A typed client is provided in `crates/wasm/js/ntesim.js` and `ntesim.d.ts`:
- Supports CommonJS, ES Modules, Node.js, Web Workers, and standard browser contexts.
- Encapsulates memory allocation, UTF-8 string encoding/decoding, pointer lifecycle, and error wrapping.
- Zero server, network, or external runtime requirements; simulation runs 100% locally in the browser or worker thread.

## 6. Preserved quality boundaries

The shared `actor_projection` invoke/CLI service also returns public action descriptors, an explicit `equipment_projection` result and per-slot research critical-roll configuration. Equipment is either `supported` with handlers/assumptions or `unsupported` with a diagnostic; an unsupported passive never becomes an empty successful handler list. Standalone static-stat queries retain their known numeric output even when the passive is unsupported. Studio rejects the unsupported equipment result before compiling a runnable scenario. Optional `slot` defaults to zero for standalone projection; Studio supplies the actor's actual slot. Rust owns packet selection, research cost/timing/input advances, eligibility and model assumptions. Browser code lowers those descriptors without consulting fixture packets or a generated combat-policy catalog. Build projection precedes rotation processing, including capacity checks for explicit energy waits. This preserves the existing research timing/cost hypotheses; it does not establish native animation, cost or cooldown behavior, or complete the pending shared Rust source interpreter.

Synthetic/partial endpoints retain the following limits. Live source reports
transport their actual Rust quality and readiness assessment unchanged; successful
parity does not upgrade that assessment.
- `content_cutoff`: Frozen at `2026-10-04`.
- `status`: Preserved as `INCOMPLETE`.
- `game_dps_computed`: Preserved as `false`.
Passing WebAssembly parity does not convert synthetic rotations or unverified native adapters into validated game DPS.

### JSON integer preservation

The direct game endpoint serializes a full borrowed report from the prepared
rotation. Preflight-resolved primary packet metadata is immutable and reused
during admissions. Talent evidence is encoded once per prepared request and
borrowed during transport serialization; typed native results retain their owned
receipt vectors. Every execution still creates fresh combat state, queue and
RNG. Full reports, partial failures and event limits retain their original
fields and values; canonical report parity ignores only build source identity.

The generic JavaScript wrapper and typed studio client share the lossless parser in `crates/wasm/js/lossless-json.js`. Unsafe integer JSON tokens are preserved as decimal strings; safe integers remain numbers. Exact fraction reconciliation uses BigInt before statistical or chart approximation. Browser classic-script callers load generated `bindings.js`, the parser and `wire.js` before `runtime.js`; studio builds bundle the shared parser and Node tests use the authored wrapper directly. Imported requests reject unsupported unsafe input quantities rather than rounding them.

All Rust JSON adapters use the workspace `serde_json` arbitrary-precision feature. Typed `Ratio` (`u64`), `ExactFraction` (`u128`), and `WideFraction` (`num_bigint`) values serialize canonically as `"<numerator>/<denominator>"` decimal strings both in JSON exports and inside `NTE wire v1` (interned as UTF-8 strings via tags `4`/`5`), preserving arbitrary precision above `u64::MAX` / `2^53 - 1` without object wrappers or backward-compatibility object shims. External raw `Scalar` / `SignedFraction` delta objects retain `{ "numerator", "denominator" }`. Integer fields above JavaScript safe range still traverse `NTE wire v1` via tag `9` string preservation. This transport contract does not relax the simulator's checked arithmetic or input bounds.


### Relative combat clock observations

Current requests and source artifacts require `clock_contract=relative-combat-v1`, `timer_policy=paused-world-v1`, `relative_duration_us` and independent `absolute_limit_us`. Reports carry actual `relative_elapsed_us` and `absolute_elapsed_us`; compact trial rows retain those scalars and nullable relative DPS. Both duration distributions come from native aggregation. A missing or obsolete clock identity requires regeneration and cannot be repaired by importing old elapsed fields.

Detailed samples retain clipped, generation-owned `timer_pauses` and interned `timer_catalog` definitions. Existing state frames carry changed timer-reference snapshots, whose deadlines use the cataloged world/object coordinate. Compact execution omits interval/catalog detail. Report import validates interval ownership/union, elapsed bounds, timer references and the first sample against the native report before replacing UI state. Selected-seed regeneration and resume bind both clocks and the policy pair to the executed source/artifact; they cannot silently mix a current sample with stale scalar observations.
