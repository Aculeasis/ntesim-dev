# DSL execution contract

Detailed interface and model reference for this [capability](spec.md). Requirements and scenarios live in that spec; this reference retains formats, bounds and technical rationale.

[Public syntax](../../../docs/NTE_DSL.md) owns authored input. This capability owns live compiler/runtime boundaries, and [script inspection](../script-inspection/reference.md) owns Rust party/stats and diagnostics without executing rotations.

Cast continuation/cancellation after switching and automatic eligible Support Skills on field entry are **native combat mechanics**, owned by B3 shared action/field services and Q2 character adapters. Their [mechanics contract](../../../docs/mechanics/shared/actor-lifecycle.md#combat-switching-mechanics) applies to all engine consumers. Q4 only submits ordinary inputs, queries settled state and verifies equivalent results; it must not introduce compiler-owned continuation rules or Support dispatch.

Native `run-script` and the Rust/WASM `run_script` API execute general exact source control flow through `PreparedSourceScenario`. Each trial owns fresh lexical and combat state; actions, waits, branches and energy gates compose without compiling combat timestamps. Native `compile-script`/WASM `compile_source` retain that live program and canonical initial scenario without executing it. Owner queries, additional source choices, stop policies and report integration remain tracked in the queue. The scheduled Studio `compile_script` adapter retains its bounded HP/energy branches and gates until browser integration and rejects authored input windows/manual target inputs/action parry assumptions that require native live execution; its compile-time scheduling is an implementation limit, not a compatibility requirement.

## Translation

Native [cooperative cancellation and continuation](../../../docs/NATIVE_LIFECYCLE.md) operate
only at complete source input boundaries. Replay checkpoints bind exact source,
compiled inputs, limits, engine/content identity and seed. Reconstruction restores
the interpreter and pending native scheduler through deterministic replay before
continuing; report observations alone are not resumable combat state. Cancelled
prefixes remain incomplete and cannot supply comparison DPS. In-progress inputs,
control evaluation and the final event drain retain their existing bounded work.

Native source canonical and executed requests declare typed
`action_admission_order=after_settled_events`. Their inputs follow the already
settled events at the same real timestamp, using the shared Observation
boundary. Native replay retains this field, including before failed admissions.
Ordinary pre-scheduled native requests use `scheduled` admission; this remains
a separate supported timing policy. Neither policy inserts elapsed time or
changes owner callback phases. Owner generation identities must not depend on
how many future authored inputs were prequeued. See
[ADR 0017](../../../docs/decisions/0017-sequential-admission-replay.md).

- Public scripts contain named builds and sequential player inputs. Native content owns packet identities, coefficients, costs, timing, equipment handlers and continuing effects. Do not serialize request internals into scripts or suggest internal IDs to repair a missing adapter.
- Research timing/primary-packet models remain internal, with assumptions attached to requests and results. Strict rejects unaccepted assumptions. A primary packet is partial coverage, never a completed attack chain or kit.
- Every reached unsupported damage dependency in a stat, equipped effect or action fails visibly. Desired scope permits documented irrelevant omissions under the [DPS policy](../product-scope/reference.md#dps-relevance-and-modeling-boundary); compiler/runtime admission changes require implementation and checks. Do not silently drop stats, unequip a requested weapon, disable automatic procs or substitute a damage scalar. Starter examples with unequipped actors must say so.
- Integer awakening in public DSL selects the first X effects. Brackets select distinct effects; count determines current level. Native requests carry sorted selected-index arrays. All 24 released owners accept arbitrary selections with implemented ordinary effects gated by identity and resonance gated by count. Unknown owners reject through the shared native validator before projection or execution; reached unsupported owner mechanics retain their existing admission boundaries. Selection capability does not complete unsupported owner mechanics.
- Repeated add stats rows sum additive contributions; one row cannot duplicate a key. Preserve innate stats and independently derived weapon/set contributions. General and all six elemental bonuses retain separate native identities and select matching packet elements at delivery.
- Manual target resistance overrides are optional exact ratios keyed by native `NATURE`, `CHAOS`, `COSMOS`, `INCANTATION`, `LAKSHANA` or `PSYCHE`; public `anima` maps to native `NATURE`. Each delivered packet selects its own element override, while physical and mental packets use common `resist`. Resistance-reduction buffs continue to apply to the selected base through the core damage formula.
- `target boss=true|false` is explicit per-target scenario metadata for the bounded Justice Executioner hypothesis. Omission defaults to false in the scenario runner only; it is not native Boss classification. Results retain the input and the reached weapon assumption, while the native Boss-identification mapping remains unresolved in the Police Rat owner.
- `target break_gauge=... max_break_gauge=... broken_duration=...` supplies the existing bounded Break profile. The compiler converts exact gauge ratios and duration seconds to request fields; shared Rust admission validates the profile. All three fields are required together; target `pack` lookups are forbidden and reject. Omission supplies no profile. Native packet metadata, depletion, Broken status, recovery and weapon extension stay in the content runtime with their existing assumptions; source compilation does not infer native eligibility, efficiency or BI settlement.
- Set selection owns its declared 2-/4-piece effects, including static bonuses exactly once. Authors supply console stats through `add stats`; no module geometry or specialization stats are computed automatically.
- The shared Rust source compiler retains bounded exact decimal/rational literals, expression results and summed build contributions through native projection. It does not round through JavaScript `number` or a fixed 1e-9 conversion first. Checks cover `0.1+0.2==0.3`, false numeric zero conditions, exact time settlement, summed additive stats and equal starting HP for `0.3-0.2` versus `0.1`. The pending shared live interpreter must preserve these rules; source compilation alone does not complete live per-trial execution. Typed flag parameters accept boolean literals and the documented exact numeric0/1 choices; numeric variables and logical query results retain their numeric contract.
- `mental%` and `shield%` compile through the native projector to `DamageUpPsychicallyBase` and `ShieldEfficiency`, adding declared contributions to equipment bonuses. Eligible Mental packets read the static bonus at delivery; implemented shields read the granter's outgoing bonus at grant before final rounding. The bindings preserve source declarations and nonnegative finite validation; they do not expose arbitrary buff or shield-capacity overrides. Unsupported producers remain unsupported.
- `start_fons` owns one immutable party starting balance, distinct from Chiz Grains/Grain Loans. Reached consumers require an explicit nonnegative integer, including zero. Contemplative Cat reads that shared value from the native scenario request; no weapon-local balance or public alias exists. Combat-time Fons changes remain unsupported until an owner defines them.

## Execution

- `content::dsl::live::Rotation` implements resumable exact control flow. `PreparedSourceScenario` supplies settled read-only fields and consumes each yielded action or explicit wait through native admission and the existing scheduler. Lexical variables, loop continuations and captured repeat counts survive suspension; each yielded occurrence carries a trial-local index and the original UTF-16 source range. Cumulative work/input/command budgets bound empty loops, zero-time yields and implicit switches. Native recovery deadlines are re-read after intervening owner events; ordinary cooldown/resource/state failures stop immediately.
- `run-script` runs one source-declared seed. The source response retains source bytes, executed input request before talent projection, per-occurrence command indices/times/ranges, a source diagnostic on failure and the native report. Source interpretation never resets continuing resources, buffs, cooldowns, pending effects or RNG. Potential input models are declared before combat initialization so owner clocks exist before their first input; only reached execution contributes resolved provenance. The two-cycle [native fixture](../../../presets/native/live-control.nte) checks all-field direct replay agreement for its supported path. General causal replay/report integration remains Q4-L7/O1-O4 work.
- The scheduled compile/Studio export still supports one HP/energy conditional whose two arms contain positive waits, or ordered integer energy gates. Its branch/gate receipts and timestamp shifts remain specific to that adapter. Native source execution composes general live conditions and loops instead. Both paths retain explicit caller energy thresholds and immediate native admission failure; neither infers thresholds from ability costs.
- Failed ordinary input admission stops the run immediately with its source line/column and typed energy/recovery/cooldown/state cause. Do not insert a wait, retry later, skip the input or execute it for free. A false authored readiness condition may skip its body. Explicit waits remain event-driven; an unresolved explicit energy gate at the horizon is incomplete execution. Executor/report waiting and idle diagnostics belong to the [runner contract](../combat-execution/reference.md#waiting-and-idle-diagnostics), not DSL syntax.
- Native source `parry=true` binds an assumed success to the actual admitted paid Dodge (Blackbird/Hathor/Haniel/Mint) or eligible charged entry (Daffodil). The request retains `parry_events` as typed `at {timestamp_us,actor_index}` or `after_action {command_index}` events. Action-bound events derive time/owner from their canonical input, validate the supported family and uniqueness, and enqueue only after successful admission at ProcCallback priority before the next sequential input. Rejected inputs schedule no parry. Source ranges follow the referenced command, including implicit switches and repeated occurrences. Existing owner effects, costs/windows, conditional finishers, charge consumption and recovery stay native; Critical Dodge and incoming HP damage remain separate assumptions. See [ADR0017](../../../docs/decisions/0017-sequential-admission-replay.md).
- Ordinary repeated attack inputs advance/reset the native chain. Comma lists and :N repeat inputs, not packets. Same-character swap is a no-op. There are no caller chain-index overrides, try/assert, generic cancellation controls or priority lists. Pending read-only readiness/resource/state/modifier/next-normal fields use current engine state, never raw request property access.
- `special` and `dash` compile to typed player inputs, preserving list/repetition order and source locations. Content owns admission timing, mode transitions, packets and costs. Adler, Nanally and Jiuyuan execute persistent aiming with native shot selection; Lacrimosa executes Flavor Variation damage, both ordinary forms and form-dependent car/truck ultimates. Supported owner Dash profiles use the declared native stamina account and cancellation gates; `critical=true` is an explicit assumed-success signal for reached owner effects. Other special owners reject explicitly. Mode is engine state, never a compiler-maintained flag or caller-selected attack parameter. Field exit clears aiming but preserves Lacrimosa's form. Pending hits retain their admitted packet identity. `final_actor_states.attack_mode` reports normal/aim/ranged/melee. The scheduled research adapter retains disclosed generic800ms special/500ms dash recovery where no native owner profile applies. Native source execution uses implemented owner timing, paid stamina, cancellation and explicitly assumed Critical Dodge eligibility; remaining owners stay bounded.
- `player_input_receipts` bind each admitted special/dash to its source command, owner, time, before/after attack mode, assumed-success flag and reached model hypotheses, including inputs without damage. Rejected inputs have no admission receipt. Report validation reconciles mode transitions and hypothesis provenance; replay and action counts identify special/dash separately from ordinary attacks, while their damage retains its native category.

Absolute timestamps retain causal order for waits, scenario events, trace and playback. All supported Ultimate cinematics and active Hotori Time Stop pause relative time. Ordinary timers preserve their remaining duration and phase on world time; deployed objects and finite action contexts follow the explicit [clock matrix](../../../docs/mechanics/shared/clocks-and-action-timing.md).

Manual inputs lower an explicitly modeled live gauge without actor admission, elapsed recovery, efficiency scaling or attack proc callbacks. Source exhaustion drains existing effects without new inputs. `source_exhausted` on an executed native request preserves that drain or defeat boundary on replay; future autonomous effects alone do not make a completed time boundary incomplete. A source input or energy wait that cannot complete before the boundary remains incomplete.

## Event-driven time advancement

The current game runner and core scheduler advance directly to queued event timestamps; microseconds are timestamp resolution, not an iteration step. Preserve this design in the pending live interpreter:

- Suspend an authored wait and advance to the earliest eligible queued event, relevant resource/state transition, wait endpoint or stop boundary. Preserve documented equal-time causal ordering and recheck explicit wait conditions after their wake-up cause settles; do not skip intervening callbacks or expiry. Ordinary failed admissions halt without scheduling retries.
- Never retry readiness once per frame/microsecond or add an arbitrary fixed polling tick. Energy/resource waits resume on relevant grants or modeled threshold crossings; state locks resume on their owner transitions. Source-level loops that issue neither an action nor a wait remain subject to nonprogress budgets, rather than being converted into scheduler polling.
- Compute elapsed-time resource changes directly, or schedule relevant threshold events, when this preserves the owner's causal behavior. Actual periodic hits, regeneration/proc ticks and observed thresholds remain modeled events; event-driven execution is not permission to omit them. Hotori mode changes update process deadlines/progress policies without a separate per-frame mode loop.
- Acceptance checks use sparse scenarios with long empty gaps: timestamp precision and gap length must not multiply readiness retries or scheduled work for an unchanged event/deadline structure. Check immediate cooldown/resource/state failure, explicit wait wake-up, intervening grants/expiry, equal-time order and ordinary-wait clipping and unresolved-energy/safety-limit diagnostics across native/CLI/WASM/Worker. With no future wake-up, retain the owning impossible/nonprogress/incomplete policy instead of inventing resource gain or advancing in tiny steps.

## Time-limited command completion

Under `stop=time`, ordinary waits, action recovery and held-input windows may
extend beyond the relative duration. The simulation stops successfully at that
endpoint and evaluates no subsequent source expression or input, including the
requested ability after a truncated implicit switch. Equal-time causal effects
settle under the existing endpoint policy; later effects remain pending and add
no damage. Scripts need no rotation-duration reserves or terminal filler loops.
Unresolved explicit energy gates, reached unsupported dependencies, failed
admissions and independent absolute/event/work limits keep their diagnostics.
