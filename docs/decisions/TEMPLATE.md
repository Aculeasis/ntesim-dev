# NNNN: Decision title

- Status: proposed
- Recorded: YYYY-MM-DD
- Decision date: YYYY-MM-DD or unknown (retrospective)
- Current owners: links to requirements and relevant contracts
- Supersedes / superseded by: record link when applicable

## Context and decision

State the problem and constraints, the requirement to preserve, the chosen mechanism and its scope. Identify transitional limits separately; link their owner rather than treating them as permanent design.

## Rationale

Explain the technical rationale, trade-offs, and reasons for the chosen approach. List alternatives considered and explain why the selected approach is appropriate.

## Consequences and assumptions

State the benefits, costs, uncertainties and assumptions that keep the choice reasonable. Explain which guarantees the choice cannot provide.

## Reconsider when

Name observable changes or evidence that justify reevaluation, and which requirement a replacement must still meet. Reconsideration does not itself grant scope or change authority.

## Verification

Link existing owner checks or define meaningful behavior to check for a replacement. Distinguish desired acceptance criteria from already passing evidence; leave runtime readiness in its existing owner.
