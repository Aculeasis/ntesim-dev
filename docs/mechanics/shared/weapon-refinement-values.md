# Serialized weapon passive parameter values

`weapon-passive-values REQUEST.json` binds an explicit native weapon ID and T1–T5 to [typed refinement definitions](../../../crates/data/src/weapon_refinements/mod.rs) and [typed weapon curves](../../../crates/data/src/weapon_curves/mod.rs). It complements constant weapon stats and gives later supported passive adapters source receipts rather than manually typed numeric values. It does not execute passives, convert units or establish released equipment availability. Original `DT_ForkUpgradeStarDataTable` and `CT_ForkBuff` exports remain cache-only.

## Binding and selection

Schema 1 requests use `global-2026-10-04`, one `weapon:native_id` and refinement 1–5 within the item limit. Native FName lookup is case-insensitive and rejects ambiguous table identities. The weapon's `UpgradeStarPackID` selects exactly the requested refinement row. Each ordered `DataList` entry retains its source pointer and `bIsPercent` hint without dividing or otherwise converting the value. English description text/keys remain available for owner guards and reports. Unused buff-class arrays/flags, costs, titles and localization fields are omitted; raw source-language report echoes are removed. Actual buffs execute through their Rust owners.

Each named curve is evaluated at the explicit serialized coordinate equal to the requested T. This is a source lookup policy; the native runtime curve consumer and its coordinate mapping remain unverified. Exactly matching keys supply exact decimal receipts. Interior coordinates without a key are supported only for `ERichCurveInterpMode::RCIM_Constant`, selecting the preceding key. Original sparse keys, Constant mode, selected key/index, method and value pointer are retained. Default sentinels and pre/post-infinity extrapolation fields are omitted and never applied. No linear/cubic interpolation is inferred.

The typed table contains 154 listed curves plus the two additional curves consumed by Tears Beneath the Mask: 156 curves and 618 exact keys. Fifty-one unused source curves are omitted, including the unapplied Nest Bird CD2 observation. Its negative reduction keys remain signed until the owner explicitly converts their magnitude; the generic nonnegative scalar service still rejects negative values. Evidence identifies `table:typed_weapon_curves`; explicit legacy overlays retain separate validation and never fill missing rows from the baseline.

Selected curves require 1–64 keys, integral unsigned coordinates in strictly increasing source order, and nonnegative exact scalar values for every key. Missing curves, invalid/duplicate keys, unsupported interpolation/extrapolation, duplicate/non-ASCII parameter IDs or malformed percent hints fail closed. At most 32 listed parameters are supported. Empty listed parameter arrays are allowed and do not imply an empty passive behavior. Request bytes are capped at 1 MiB by the CLI.

The [Mind Royale owner card](../weapons/mind-royale/passive.md) owns its listed curve values and unit/trigger model. This service retains raw source coordinates and methods without executing a passive.

## Reports, verification and quality

The CLI audits the package and binds four metadata hashes, the exact request hash and engine fingerprint. Definition/curve constants are typed Rust inputs. Exit 0 means the listed parameter values resolved successfully; quality remains `INCOMPLETE`, `game_dps_computed:false`, `passive_adapter_complete:false` and `release_status:unverified`. `listed_parameters_resolved:true` refers only to the DataList, not complete effect dependencies or behavior.

`tools/verify_weapon_passive_values.py` checks all 51 frozen native weapon candidates across five refinements: 255 requests and 770 parameter references, comprising 611 exact keys and 159 Constant interior selections. It uses cache-only original exports and Fraction arithmetic, compares every consumed parameter/description and sparse key/mode, source pointers, byte-identical replay/relocation, malformed request rejection and changed audited-input rejection. Current per-request hashes/evidence go to `target/verification/weapon-passive-values/`; `--refresh-receipt` writes the current copy under `target/reviews/q10-weapon-passive-values/`. Rust mutations separately cover missing rows/curves, duplicate names, unsupported mode, nonintegral/duplicate/outside coordinates and invalid values. Native/WASM/actual Worker checks also exercise equipped owners, aggregation and replay.

Native release status, actual curve consumer, units/percent semantics, triggers, recipients, refresh/ICD, resources, clocks, off-field behavior and stat application remain unresolved. This numeric binding closes none of the full passive, adapter or strict Reference guide gates.
